## Reproduction and fix

Two unresolved GitHub review findings were discovered during the final GraphQL
readback:

1. Inline type-only imports could be resolved even though TypeScript erases them.
   The existing emitted-runtime parser already fixed the cause. A new exact
   `import { type DeclarationOnlyProps } from "./declarations"` fixture backed by
   `declarations.d.ts` passed before any additional production edit and now locks
   the declaration-only case.
2. A non-directive helper reached inside a client subtree could promote its nested
   client import into an extra server-to-client reference. The new regression first
   failed with actual references
   `NestedClient#default, RootClient#default` where only `RootClient#default` was
   expected.

The production traversal now carries inherited client-subtree context and keys
completed visits by both file and server/client context. This removes false nested
boundaries while still re-evaluating a shared helper reached directly from a server
path, where its nested client import is a real boundary.
